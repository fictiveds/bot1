# Генератор Экспериментальной Музыки

Этот Python-скрипт предназначен для создания странных звуковых файлов и экспериментальных музыкальных композиций. Он использует различные техники генерации и обработки звука для получения уникальных и непредсказуемых результатов.

## Возможности

*   Генерация базовых звуковых волн: синус, квадрат, пила, шум.
*   Применение различных аудиоэффектов:
    *   Задержка (Delay/Echo)
    *   Фильтрация (Low-pass, High-pass)
    *   Реверберация (упрощенная)
    *   Гранулярный синтез (упрощенный)
*   Смешивание и наложение множества звуковых слоев.
*   Создание полноценных композиций со случайным панорамированием и применением эффектов.
*   Управление через интерфейс командной строки (CLI).

## Установка

1.  Клонируйте репозиторий (или просто скачайте файл `sound_generator.py`).
2.  Убедитесь, что у вас установлен Python 3.x.
3.  Установите необходимые зависимости. Рекомендуется использовать виртуальное окружение:

    ```bash
    python -m venv venv
    source venv/bin/activate  # для Linux/macOS
    # venv\Scripts\activate  # для Windows
    ```
4.  Установите библиотеки из файла `requirements.txt`:

    ```bash
    pip install -r requirements.txt
    ```
    Вам также может потребоваться установить `ffmpeg` для работы `pydub` с различными аудиоформатами (хотя для WAV он обычно не нужен). Инструкции по установке `ffmpeg` можно найти на [официальном сайте](https://ffmpeg.org/download.html).

## Использование

Скрипт запускается из командной строки. Убедитесь, что вы находитесь в корневой директории проекта (`experimental_sound_generator`).

**Основные аргументы:**

*   `-o ИМЯ_ФАЙЛА`, `--output_file ИМЯ_ФАЙЛА`: Имя выходного WAV-файла для композиции (по умолчанию: `experimental_music.wav`).
*   `-d ДЛИТЕЛЬНОСТЬ`, `--duration ДЛИТЕЛЬНОСТЬ`: Длительность композиции в секундах (по умолчанию: `30`).
*   `-l КОЛИЧЕСТВО_СЛОЕВ`, `--layers КОЛИЧЕСТВО_СЛОЕВ`: Количество слоев в композиции (по умолчанию: `5`).
*   `--seed SEED`: Целочисленное значение для инициализации генератора случайных чисел (для воспроизводимости результатов).
*   `-s ИМЯ_ФАЙЛА_ЗВУКА`, `--single_sound_file ИМЯ_ФАЙЛА_ЗВУКА`: Сгенерировать один случайный звук и сохранить его в указанный файл (вместо полной композиции).

**Примеры команд:**

1.  **Сгенерировать композицию по умолчанию (30 секунд, 5 слоев) и сохранить в `experimental_music.wav`:**
    ```bash
    python -m cli.main
    ```

2.  **Сгенерировать 60-секундную композицию с 10 слоями и сохранить в `my_composition.wav`:**
    ```bash
    python -m cli.main -o my_composition.wav -d 60 -l 10
    ```

3.  **Сгенерировать композицию с использованием определенного зерна для случайности:**
    ```bash
    python -m cli.main --seed 42
    ```

4.  **Сгенерировать один случайный звук и сохранить его в `random_sound.wav`:**
    ```bash
    python -m cli.main -s random_sound.wav
    ```

## Структура кода

Проект имеет следующую структуру:

*   **`experimental_sound_generator/`**: Корневая папка.
    *   **`cli/main.py`**: Точка входа приложения, обработка аргументов командной строки.
    *   **`composer/composition.py`**: Логика создания музыкальных композиций.
    *   **`audio_engine/`**: Пакет для низкоуровневых операций со звуком.
        *   `waveforms.py`: Генерация базовых звуковых волн (NumPy).
        *   `effects.py`: Реализация аудиоэффектов (NumPy).
        *   `pydub_utils.py`: Утилиты для работы с `pydub`, конвертация и обертки для `AudioSegment`.
    *   **`utils/constants.py`**: Общие константы (например, `SAMPLE_RATE`).
    *   **`nodal_engine/`**: Пакет для нодального (модульного) звукового движка.
        *   `core.py`: Базовые классы `Module`, `AudioModule`, `ControlModule`, а также `InputConnector`, `OutputConnector` и `ModulationType`.
        *   `modules.py`: Конкретные реализации модулей (осцилляторы, эффекты, LFO, ADSR, SignalScalerOffset).
        *   `graph.py`: Класс `SoundGraph` для управления графом модулей и рендеринга.
    *   `requirements.txt`: Список зависимостей.
    *   `README.md`: Этот файл.
    *   `.gitignore`: Файл для исключения ненужных файлов из Git.

## Работа с Нодальным Звуковым Движком (Экспериментально)

Помимо основной системы генерации случайных композиций, в проект интегрирован нодальный (модульный) звуковой движок. Этот подход позволяет конструировать звук путем соединения различных модулей (генераторов, эффектов, управляющих сигналов) в единый "звуковой граф", что открывает путь к более контролируемому и гибкому созданию звуковых текстур и эффектов.

### Основные концепции

*   **Модули (`Module`, `AudioModule`, `ControlModule`)**: Фундаментальные блоки для построения звука, определенные в `nodal_engine.core` и реализованные в `nodal_engine.modules`.
*   **Коннекторы (`InputConnector`, `OutputConnector`)**: Каждый модуль имеет именованные входы и выходы. `OutputConnector` одного модуля может быть подключен к `InputConnector` другого.
*   **`SoundGraph`**: Контейнер из `nodal_engine.graph`, управляющий модулями, их соединениями и процессом рендеринга.

### Гибкое Управление Параметрами и Модуляцией

Ключевой особенностью нодального подхода является возможность модуляции параметров. Каждый `InputConnector` модуля обладает следующими атрибутами, которые определяют, как он обрабатывает входящий сигнал (от другого модуля) и собственное значение по умолчанию:

*   **`default_value`**: Базовое значение параметра, если к входу ничего не подключено или если тип модуляции это предполагает (например, при `ADD` или `MULTIPLY`).
*   **`modulation_type`**: Определяет, как сигнал с подключенного выхода модулятора комбинируется с `default_value` параметра:
    *   `ModulationType.REPLACE`: Значение с модулятора полностью заменяет `default_value`.
    *   `ModulationType.ADD`: Значение с модулятора добавляется к `default_value`.
    *   `ModulationType.MULTIPLY`: `default_value` умножается на значение с модулятора.
*   **`scale`**: Коэффициент, на который умножается сигнал *с модулятора* перед его применением (до комбинации с `default_value`). Позволяет настроить "глубину" модуляции.
*   **`offset`**: Смещение, которое добавляется к сигналу *с модулятора* (после масштабирования `scale`) перед его применением.

Эти атрибуты позволяют гибко настраивать взаимодействие между модулями. Например, выход LFO, колеблющийся от -1 до 1, можно смасштабировать и сместить, чтобы он изменял частоту другого осциллятора в нужном диапазоне или добавлял "вибрато" определенной глубины.

### Пример использования нодального движка (`--nodal_example`)

Для демонстрации возможностей нодального движка можно использовать опцию `--nodal_example ИМЯ_ФАЙЛА.wav` в командной строке. Этот пример создает следующий звуковой граф:

1.  **LFO для модуляции частоты (`lfo_freq`)**: Генерирует синусоидальный сигнал с частотой 5 Гц и амплитудой 1.0 (диапазон от -1.0 до 1.0).
2.  **ADSR-огибающая (`adsr_amp`)**: Формирует общую амплитудную огибающую для звука (Attack: 0.2с, Decay: 0.3с, Sustain: 0.7, Release: 0.5с).
3.  **Синусоидальный осциллятор (`sine_osc`)**: Является основным источником звука.
    *   **Модуляция Частоты**:
        *   Его вход `frequency_in` имеет базовое значение (default_value) 220 Гц.
        *   К этому входу подключен выход `lfo_freq`.
        *   Тип модуляции для `frequency_in` установлен как `ModulationType.ADD`.
        *   Параметр `scale` для `frequency_in` установлен в `20.0`.
        *   **Результат**: Частота `sine_osc` будет колебаться вокруг 220 Гц с глубиной +/- 20 Гц (220 Гц + LFO_выход * 20), создавая эффект вибрато.
    *   **Модуляция Амплитуды**:
        *   Его вход `amplitude_in` имеет базовое значение 0.0.
        *   К этому входу подключен выход `adsr_amp`.
        *   Тип модуляции для `amplitude_in` установлен как `ModulationType.REPLACE`.
        *   **Результат**: Амплитуда `sine_osc` будет полностью управляться сигналом с ADSR-огибающей, формируя динамику звука во времени.
4.  **Мастер-выход**: Выход осциллятора `sine_osc` назначен мастер-выходом графа.
5.  **Триггер ADSR**: Огибающая запускается один раз в начале.

При запуске примера генерируется 4-секундный WAV-файл, в котором слышен звук синусоиды с вибрато по частоте и общей амплитудной огибающей ADSR. Это демонстрирует, как различные модули могут быть соединены для создания более сложных и динамичных звуков, чем при использовании отдельных функций генерации.

### Дальнейшее развитие

Текущая реализация нодального движка является основой. В планах:
*   Добавление большего количества модулей: генераторов (например, FM-синтез), эффектов (более сложные фильтры, хорус, фленджер) и управляющих модулей (секвенсоры, генераторы случайных чисел с разными распределениями).
*   Возможность модуляции параметров `scale` и `offset` у `InputConnector`.
*   Более сложная система маршрутизации и управления "гейт" (gate) сигналами для ADSR и других модулей, требующих запуска.
*   Улучшение производительности и оптимизация обработки блоков.

Вы можете экспериментировать, модифицируя код в `cli/main.py` (в секции `--nodal_example`) для создания и тестирования собственных звуковых графов.
